# Scaling benchmark, Apple M4: per-cell medians

Host: Apple M4 (10 cores, 32 GB), macOS 26.5, `darwin-arm64`, FP policy `fma`.
`mafft-rs` CLI and `pymafft` at main `91903cc` (built 2026-11-20); C MAFFT 7.526,
in-tree build. 3 replicates per (cell, implementation). Source TSV:
`scaling_darwin-arm64_2026-11-24.tsv` (2610 rows); the tables below are
`benchmarks/scaling.py summarize` output plus a per-mode digest.

Provenance of the rows: the `mafft-rs` and `pymafft` runs were all made
between 2026-11-20 and 2026-11-24 at `91903cc`. The C runs are the cached
runs of the earlier sweeps on the same machine and the same C build
(2026-11-02 to 2026-11-19; `scaling.py` reuses a cached cell), so C and
Rust were not interleaved within one session. 1-minute load average at the
start of each run: C median 2.0 (1.5 – 8.0), `mafft-rs` median 2.1
(1.0 – 8.9), `pymafft` median 2.0 (1.0 – 10.2); a `--thread 8` cell raises
the load seen by the cell that follows it.

Column meaning: times are wall-clock seconds, median [IQR] over 3
replicates; RSS is the median peak RSS in MB; `C = Rust` is byte-identity
of the `mafft-rs` output with C's output *at the same thread count*. The
33 `no` cells are all `--thread 8` cells where C's own `--thread 8` output
differs from C `--thread 1` (C's threaded refinement is nondeterministic;
in 32 of them C gave 3 different outputs in 3 runs). In every one of those
cells `mafft-rs --thread 8` equals `mafft-rs --thread 1` and, where the
`--thread 1` cell was run (23 of the 33), C `--thread 1`.
